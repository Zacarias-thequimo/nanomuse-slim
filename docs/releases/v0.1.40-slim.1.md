# nanoMuse 0.1.40-slim.1 · Light

🐉 **nanoMuse `0.1.40-slim.1` “Light”** is 0.1.40 with a smaller desktop for Linux.

The full Linux `.deb` weighed 244 MB: Electron's Chromium, the dsh tree and a
bundled Python runtime, each a runtime of its own. This variant trims all three
and splits the packaging, so the desktop fits machines with 2 CPUs and 4 GB of
RAM. Nothing about the agent changes — the same bundle, the same relay, the
same hands.

## Highlights

- **Smaller full packages.** Maximum `.deb` compression, only the `en-US` and
  `zh-CN` Electron locales, fewer docs and fixtures inside `dsh/node_modules`,
  and a symbol-stripped runtime build.
- **`-min` Linux packages.** No bundled runtime inside (`-min.deb`,
  `-min.AppImage`, `-min.tar.gz`); the hands run from `nanomuse` on PATH
  (`scripts/install-runtime-linux.sh`, or unpack
  `nanomuse-server-<version>-linux-x64.tar.gz`). `NANOMUSE_PY` wins over both.
- **A low-memory profile.** At or below 4.5 GB of RAM the shell drops the GPU
  process, caps the renderer and Host heaps and halves the libuv threads
  (`NANOMUSE_LOW_MEM=0` disables it, `=1` forces it).
- **A Tauri shell in progress** (`harness/tauri/`, Linux first): the same
  staged `dsh/` with the system's WebKitGTK instead of bundled Chromium. Not
  packaged yet.

## Upgrade Notes

- **Linux: prefer `-min` on small machines.** Install the `-min.deb`, then
  `scripts/install-runtime-linux.sh --from-pypi` (or unpack the server
  tarball) so the hands work. The full `.deb` keeps working as before.
- **The desktop installers are not notarised.** On macOS open the app once
  from *System Settings → Privacy & Security → Open Anyway*; on Windows click
  *Run anyway*. They arrive a little after the tag — CI builds them from it —
  and `SHA256SUMS-desktop.txt` lists every checksum.
- **Where to get it.**

  | | |
  |---|---|
  | Linux x64 | `nanoMuse-Desktop-0.1.40-slim.1-linux-x64.deb` (full) / `-min.deb` (no runtime) / `.AppImage` / `.tar.gz`, plus `nanomuse-server-0.1.40-slim.1-linux-x64.tar.gz` |
  | Windows 10+ | `nanoMuse-Desktop-0.1.40-slim.1-win-x64.exe` |
  | macOS 12+ | `nanoMuse-Desktop-0.1.40-slim.1-mac-arm64.dmg` / `-mac-x64.dmg` (and `.zip`) |

🐉 **nanoMuse `0.1.40-slim.1`「Light」**：0.1.40 的轻量桌面版，只动 Linux 打包。

完整版 Linux `.deb` 有 244 MB：Electron 的 Chromium、dsh 目录和自带的 Python
runtime，各带一套运行时。这个版本把三处都削了，并拆分打包，让桌面版能在
2 核 4 GB 的机器上跑。Agent 本体没变——同一个 bundle、同一个 relay、同一双手。

### 亮点

- **完整包更小。** `.deb` 最高压缩，只带 `en-US` 和 `zh-CN` 两个 Electron 语言包，
  `dsh/node_modules` 里少了文档和测试文件，runtime 做了符号裁剪。
- **`-min` Linux 包。** 里面没有 runtime（`-min.deb`、`-min.AppImage`、`-min.tar.gz`），
  动手功能走 PATH 里的 `nanomuse`（`scripts/install-runtime-linux.sh`，或解压
  `nanomuse-server-<version>-linux-x64.tar.gz`）。`NANOMUSE_PY` 优先级最高。
- **低内存模式。** 内存 4.5 GB 及以下自动生效：去掉 GPU 进程，限制渲染进程和 Host
  的堆，libuv 线程减半（`NANOMUSE_LOW_MEM=0` 关掉，`=1` 强制开）。
- **Tauri 壳在写了**（`harness/tauri/`，先做 Linux）：同一份 `dsh/`，用系统 WebKitGTK
  代替自带的 Chromium。还没打包。

### 升级说明

- **小机器装 `-min`。** 先装 `-min.deb`，再跑 `scripts/install-runtime-linux.sh --from-pypi`
  （或解压 server 包），动手功能就有了。完整版 `.deb` 照常用。
- **桌面安装包没有经过公证。** macOS 第一次在「系统设置 → 隐私与安全性」里点「仍要打开」，
  Windows 点「仍要运行」。安装包会比 tag 晚一点到——CI 从 tag 构建它们；
  `SHA256SUMS-desktop.txt` 列出了所有校验值。
